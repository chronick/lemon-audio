smpl analyze

One endpoint. Audio bytes in, a structured descriptor report out — loudness, spectral shape, and quality-control flags an LLM can actually read. Waveforms are opaque to a language model; measurements are not.

POST /analyze

Raw bytes in the request body, Content-Type: audio/*. No multipart, no upload form, no account. The server writes the bytes to a temp file, runs the smpl pipe read | loudness | spectral | qc | view, and deletes the file before it replies.

# the four-second demo loop shipped with smpl
curl -LO https://chronick.github.io/smpl/assets/loop.wav

curl --data-binary @loop.wav \
     -H 'Content-Type: audio/wav' \
     'http://localhost:8791/analyze?name=loop.wav'

The response is JSON with three keys — report (the Markdown table smpl's view renders), features (grouped by role), and frames (every raw NDJSON frame, if you want the lineage and content hashes):

{
  "report": "# smpl analysis report\n\n**5 frame(s):** …",
  "features": {
    "loudness": {
      "loudness.integrated_lufs": -20.79,
      "loudness.true_peak_dbtp": -6.71,
      "loudness.max_short_term_lufs": -20.71
    },
    "spectral": { "lowlevel.spectral_rolloff": {"mean": 5228.39, …}, … },
    "qc": {
      "qc.clipping.detected": false,
      "qc.snr_db": 13.91,
      "qc.lossy.spectral_cutoff_hz": 19993.6,
      "qc.lossy.confidence": 0.001
    }
  },
  "frames": [ … ]
}

That is the same loop, and those are the same numbers, the smpl README quotes for a local install — the endpoint adds no analysis of its own.

Limits

  • 25 MB request cap — a loop or a stem, not an album.
  • 120 s analysis budget per request.
  • audio/* content types only; anything else is a 415.
  • Stateless. Nothing is stored, nothing is queued, no bytes survive the response.
Status. Analysis is done by the open-source smpl engine, shelled as a subprocess — this service is a thin stdlib HTTP wrapper around read | loudness | spectral | qc | view and adds no DSP. The endpoint is incubating under lemon.audio and self-hosted; expect it to move to its own subdomain. There is no uptime promise and no API key.

The engine

smpl is a composable, content-addressed audio-analysis toolchain you pipe like jq: one self-describing NDJSON frame per line, heavy bytes referenced by hash rather than carried. Everything this endpoint returns, you can produce locally.
